Parquet Validator

Validate a Parquet file against a ruleset — entirely in the browser, with no upload. Load a Parquet file (or connect a DuckDB server), define rules per column or table-wide, and get a report: which rule holds, which does not, how many rows violate it — with a jump into the offending rows.

Flow

  1. Load a file — Parquet by drag & drop / picker, or a table from a DuckDB server. A preview shows the first rows of the loaded data.
  2. Define rules — by hand via + Rule, or automatically via Suggest rules (derives proposals from a quick profile: no-null columns, key candidates, small value sets, dominant patterns, numeric ranges).
  3. Validate — the report shows the score, the valid rows, and each rule's violations. For a failing rule, Rows opens a sample of the violating rows.

Rule types

  • Not null — the column must contain no NULLs.
  • Unique — no duplicate values.
  • Allowed values — every value comes from a fixed set.
  • Range — numeric, between a minimum and a maximum.
  • Length — character length between a minimum and a maximum.
  • Regex — a full match against a regular expression.
  • Dominant pattern — the value matches one of the column's dominant structural patterns (derived from the pattern analysis).
  • Type-castable — the value can be cast to the target type.
  • Trimmed — no leading/trailing whitespace.
  • Reference — the value exists in a column of a reference table (foreign key; add a reference Parquet above).
  • Custom SQL — any boolean expression per row.
  • Row count — the table has at least/at most N rows.

Value checks pass on NULL — absence is checked only by the Not null rule, so a missing value is never penalised twice. Each rule has a severity (error or warning); the overall status fails as soon as one error rule is violated, warnings only lower the score.

The ruleset as a contract

Save ruleset downloads the rules as portable JSON, Load ruleset reads them back. Define the expectations for a table once and re-check every new export — a repeatable data contract. Report ⤓ exports the result as Markdown.

Everything runs locally via DuckDB-WASM. No data is uploaded.
