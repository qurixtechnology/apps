Parquet Validator

Prüft eine Parquet-Datei gegen einen Regelsatz — vollständig im Browser, ohne Upload. Lade eine Parquet-Datei (oder verbinde einen DuckDB-Server), definiere pro Spalte oder tabellenweit Regeln und erhalte einen Bericht: welche Regel hält, welche nicht, wie viele Zeilen verstoßen — mit Absprung in die konkreten Zeilen.

Ablauf

  1. Datei laden — Parquet per Drag & Drop / Auswahl oder eine Tabelle von einem DuckDB-Server. Eine Vorschau zeigt die ersten Zeilen der geladenen Daten.
  2. Regeln definieren — von Hand über + Regel oder automatisch über Regeln vorschlagen (leitet aus einem Schnellprofil Vorschläge ab: nicht-null-Spalten, Schlüsselkandidaten, kleine Wertemengen, dominante Muster, Wertebereiche).
  3. Validieren — der Bericht zeigt Score, gültige Zeilen und je Regel die Verstöße. Bei einer fehlgeschlagenen Regel öffnet Zeilen eine Stichprobe der verletzenden Zeilen.

Regeltypen

  • Nicht null — die Spalte darf keine NULL-Werte enthalten.
  • Eindeutig — keine doppelten Werte.
  • Erlaubte Werte — jeder Wert stammt aus einer festen Menge.
  • Wertebereich — numerisch zwischen Minimum und Maximum.
  • Länge — Zeichenlänge zwischen Minimum und Maximum.
  • Regex — voller Treffer gegen ein reguläres Ausdrucksmuster.
  • Dominantes Muster — der Wert passt zu einem der dominanten Struktur­muster der Spalte (aus der Musteranalyse abgeleitet).
  • Typ-castbar — der Wert lässt sich in den Zieltyp umwandeln.
  • Getrimmt — kein führender oder nachgestellter Leerraum (Wert = trim(Wert)); Verstoß sind z. B. " Berlin" oder "Berlin ".
  • Referenz — der Wert existiert in einer Spalte einer Referenztabelle (Fremdschlüssel; Referenz-Parquet oben hinzufügen).
  • Eigenes SQL — eine boolesche Bedingung, die fehlerhafte Zeilen kennzeichnet (TRUE = Verstoß, wie bei dbt-Tests); z. B. betrag < 0 markiert alle Zeilen mit negativem Betrag als Verstoß.
  • Zeilenzahl — die Tabelle hat mindestens/höchstens N Zeilen.

Wertprüfungen bestehen bei NULL — fehlende Werte prüft ausschließlich die Nicht-null-Regel, damit ein fehlender Wert nie doppelt bestraft wird. Jede Regel hat einen Schweregrad (Fehler oder Warnung); der Gesamtstatus schlägt fehl, sobald eine Fehler-Regel verletzt ist, Warnungen senken nur den Score.

Regelsatz als Vertrag

Regelsatz speichern lädt die Regeln als portable JSON-Datei herunter, Regelsatz laden liest sie wieder ein. So definierst du die Erwartungen an eine Tabelle einmal und prüfst jeden neuen Export erneut — ein wiederholbarer Datenvertrag. Bericht ⤓ exportiert das Ergebnis als Markdown.

Alles läuft lokal per DuckDB-WASM. Es werden keine Daten hochgeladen.
