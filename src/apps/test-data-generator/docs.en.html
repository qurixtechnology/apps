What does this app do?

The Test Data Generator creates realistic, referentially-linked test data for typical business domains — entirely in the browser, with no data leaving your machine. Generation, preview and export all run locally on DuckDB-WASM.

Domains

  • Customers — people and companies with address, e-mail, phone, segment.
  • Orders & line items — orders with item lines, linked to customers, products and employees.
  • Transactions — financial bookings with amount, IBAN, category, optional customer/order reference.
  • Products & employees — product master data and staff with department, role, salary.

Tables are linked through real foreign keys (e.g. every order references an existing customer), so joins work when testing. Dependent tables are added automatically when needed.

Derive from a file

As an alternative to the templates, “Derive from a file” imports an existing file (CSV, TSV, Parquet, JSON, NDJSON — the shared import widget). It does not copy the data; it learns a model and generates new, synthetic rows that mirror the file:

  • Structure — the same columns and exact data types.
  • Statistics — value ranges (min/max), mean/spread for numbers, date spans, and the per-column NULL rate.
  • Column type & Faker — for text columns the meaning is detected (name, company, city, street, country, reference …). Such fields are generated fully synthetically by a Faker (from the DE/EN locale pools), so no original characters remain — not even shared name fragments.
  • Patterns — structured fields (codes, phone, IBAN, postal, e-mail) follow their character pattern (e.g. CUST-9999); only non-personal structure (a +49 , @host) is kept while variable positions are re-rolled.
  • Categories — columns with few distinct values are treated as categories and kept as in the original (resampled by frequency).

Turning categorisation off: for any column detected as a category, the “as category” switch in the structure overview can be disabled. Real values are then no longer kept; instead they are generated fully synthetically via the Faker — important for personal fields (e.g. names on a bank statement).

The quality sliders apply on top here too — the default is clinically clean, so the file is reproduced faithfully at first.

Quality level

Four presets — from clinically clean through light and realistic to heavily flawed. The fine-tune section controls individual issue types on a continuous scale:

  • Missing values (NULL), duplicates, typos,
  • Format inconsistency (mixed date, number, phone and country formats — then stored as text),
  • Outliers (negative prices, impossible dates, extreme amounts) and
  • Whitespace & casing.

Reproducibility

Same seed + same settings ⇒ exactly the same data. The 🎲 button rolls a new random seed. The DE/EN region controls names, addresses, IBAN and phone formats.

Export

To every format DuckDB supports: Parquet, CSV, JSON, NDJSON, Excel (xlsx), ODS, Markdown, HTML. With multiple tables, Excel/ODS is written as one workbook with a sheet per table; other formats as a ZIP with one file per table.
